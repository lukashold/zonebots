Game.native_cranes owns the single persistent 240-slot pool. NativeWorld has
no crane pool. A phase belongs to a physical identity (mission epoch plus the
existing upstream slot generation) and an explicit renderer binding. Only the
real fresh 41b210 constructor receipt establishes known 9a=0. That receipt
survives world=None and world import. A fresh foot record contains the known
phase and constructor96 receipt, with no work auxiliary. A duplicate import is not a
second constructor. Actual 57ff0 retains 9a, writes 86=FF and uses the existing
owner for 28=2084. Entry, ordinary unload, APC occupation and APC unload rebind
the same physical record. Death or a kind/entity change does not infer a fresh
byte. New construction and explicit mission reset invalidate the old identity.
